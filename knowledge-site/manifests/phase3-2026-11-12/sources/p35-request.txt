## 6.2 保持原计时协议

原协议：

`mla-contiguous-host-sync-v1`

原设置：

```text
Warmup:
    5

    None
```

必须保留：

- 全部原始样本。

- Mean。
- Std。

## 6.3 ABBA 执行

在资源和预算允许时，采用：

```text
A = Control Baseline
B = Delayed Store Wait

Run 1: A
Run 2: B
Run 3: B
Run 4: A
```

也可以根据现有确认工具执行顺序反转的交错批次：

```text

A
A
B
```

需要注意：

- A 和 B 都是独立真实执行。
- 使用相同输入和计时协议。
- 不在测试中修改 Kernel。
- 避免其他 TPU 工作干扰。
- 不将编译时间混入正式计时。
- 每个 Run 具有独立证据。
- 保存完整执行顺序和时间。

不要把 20 个同一 Run 内的样本简单当成 20 次独立跨 Run 实验。

## 6.4 统计与稳定性分析

必须分别比较：

### Host Latency

- A/B Median。
- A/B Mean。
- Run-to-Run Variance。
- Within-Run Variance。
- 配对差异。
- Speedup。
- Latency Reduction。

### Profile Program Duration

- Program Duration。
- Prepare Duration。
- Attention Duration。
- 同一采集口径下的变化。
- 是否存在可重复的 Program 改善。

如果计算置信区间，必须说明统计单位、配对方式和样本独立性假设，不得把存在相关性的单 Run 样本当成独立实验夸大可信度。

需要区分：

1. Host 改善，Program 也改善。
2. Host 改善，但 Program 不明显。
3. Program 改善，但 Host 没有明显改善。
4. 两者都不稳定。
5. 数据不足，无法判断。

不能因为某一次 Host Latency 更快就宣称稳定收益。

## 6.5 预先固定判断规则

在查看新结果前，读取已有 Benchmark / Promotion Contract。

如果已有稳定性判断阈值，使用原规则。

如果没有，先形成明确的独立确认规则，记录版本和适用范围，然后执行复测。

不能看到 Candidate 更快后再调整阈值。

不要擅自改写 Store 已完成的历史晋升。

需要区分：

- 本轮按现有 `consider` 规则的晋升。
- 跨独立 Run 的稳定收益确认。

两者可以有不同结论。

## 6.6 ABBA 结果处理

若确认稳定改善：

- 保存原始测量。
- 保存统计。
- 保存 Profile。
- 更新相应证据。
- 标记已完成独立确认。

若没有确认：

- 保留原始 Result。
- 保留历史 Best。
- 保存无稳定收益的结论。
- 不删除或改写旧 Run。
- 允许未来有依据地重新探索。

若结果不确定：

- 明确标记 inconclusive。
- 不能宣称成功。
- 根据剩余预算判断是否进行有限追加测量。

不能为了满足数量要求生成重复 Plan。

不能把第一轮的 Plan 简单改名后重新执行。

必须体现第一轮实验结果对第二轮方法选择的影响。

## 7.5 可能的研究方向

以下仅供 Analyzer 分析，**不是必须执行的 Plan**。

### 方向一：Store Wait 调度

研究：

- 延迟 store.wait 的合法同步位置。
- 不同 Tile 下的依赖关系。
- 是否存在其他 Wait 可以合法后移。
- 额外控制开销。
- 潜在 DMA overlap。
- 正确性风险。

不能未经证明地继续移动同步点。

### 方向二：Single Tile

第一轮 Single Tile 接近 Baseline。

需要进一步理解：

- 哪些 Shape 真正是单 Tile。
- 是否适用于特定 Decode 配置。
- 零长度边界。
- Online Softmax 状态初始化。
- Mask / Length 特殊情况。

### 方向三：Tile Size

第一轮：

```text
Tile 512:
    slower

Tile 256:
    slower
```

分析：

- Program Duration 增加。
- Tile 数量增加。
- 计算/搬运调度变化。
- 调用开销。
- Live Memory。
- 其他可能因素。

不要仅因为较小 Tile 在当前 Shape 下退化，就断言所有 Shape 下都必然退化。

### 方向四：Compact New Row

第一轮：

```text
compact-new-row:
    slower
```

可以分析：

- Prepare 减少的数据量。
- Attention 广播开销。
- Layout Conversion。
- 不同 Shape 的影响。
- 额外控制逻辑。

该方向不要求必须继续执行。

### 方向五：Knowledge 中其他方法

允许从已有 Knowledge 和 project2 历史实验中提出新的方法。

但每个方法必须有代码映射与合理依据。

不能仅仅引用论文标题就执行代码修改。
