# 0. 项目背景与最终目标

我们正在开发 RSI-Kernel-Agent。

项目的最终目标是构建一个能够自主优化 TPU Kernel 的系统：

1. 分析当前 Kernel 的代码和性能瓶颈。
2. 从开源资料和已有知识库中搜索优化方法。
3. 读取之前的优化历史和实验经验。
4. 利用数学模型分析不同优化方向。
5. 生成多个有依据的优化 Plan。
6. 自动生成独立 Candidate。
7. 在真实 TPU 上执行实验。
8. 验证正确性和性能。
9. 将结果写回 Memory。
10. 根据新的实验结果进入下一轮优化。

目前已经完成：

| 阶段 | 内容 | 状态 |
|---|---|---|
| Phase 2A | Core Foundation | 完成 |
| Phase 2B | Knowledge / Memory | 完成 |
| Phase 2C | Profiler / Analyzer | 完成 |
| Phase 2D+ | Workflow / Controller / Synthetic E2E | 完成 |
| Phase 3 | Real Hardware Integration | 当前开始 |

Phase 2D+ 的最新验收报告显示：

- 根级测试：230 项。
- 229 项通过。
- 1 项跳过。
- 0 项失败。
- 既有 MCP 回归：5/5 通过。
- 已完成两轮 Synthetic RSI Demo。
- 已验证多 Plan、Candidate、Repair、Recovery 和 Memory 更新。

注意：这些是 Phase 2 的软件验收结果，不代表真实 Kernel 或 TPU 性能已经验证。

必须区分：

1. JIT / Compile Time。
2. Warmup。
3. Device Execution。
4. Host / Device Transfer。
5. End-to-End Latency。

JAX 有异步执行机制。

计时必须等待设备执行真正完成。

例如：

```python
result = kernel(...)
result.block_until_ready()
```

如果输出为多个数组或 pytree，确保所有相关输出都完成。

注意：

`perf_counter + block_until_ready()` 测得的时间不应未经说明就叫作纯设备 Kernel 时间。

必须记录：

- 每次原始 Latency。
- Warmup 次数。
- Measurement 次数。
- Median。
- Mean。
- Standard Deviation。
- Min / Max。
- P25 / P75（适用时）。
- Outlier 规则。
- 环境指纹。
- Benchmark Protocol Version。

Baseline 与 Candidate 应使用相同协议和可比环境。

尽可能采用配对或交错测量观察设备漂移。
