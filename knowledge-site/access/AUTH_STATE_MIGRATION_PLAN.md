## 建议的新位置与接口

后续批准后，可统一由一个路径解析函数选择仓库外 `%LOCALAPPDATA%/Zhixu/<library-id>/auth/`。这是提议，尚非可用配置项。library-id 应稳定标识知识库，不能只由当前位置派生，否则再次移动知识库会丢失关联。记录非秘密 library-id/位置映射，认证文件本身留在安全目录。

服务、launcher、owner_admin、分享器、stop 与 MCP 必须从相同 resolver 取位置；支持显式、经过验证的运行状态目录。路径必须在允许的本机状态根内，拒绝网络共享、symlink/junction 逃逸和意外落入内容区。现有本地服务 token、用户授权、已批准浏览器、cookie/CSRF 契约和公网 origin 都应维持兼容；不通过重新生成空数据库“完成迁移”。

5. 失败时先停止新写入，明确哪份状态是最新权威再回退；不能让新旧数据库同时接受写入。保留迁移记录与错误，不覆盖更新后的授权。

## 验收与不变量

- 无秘密进入 content、Git、生成报告或外部服务；源/目的权限满足批准策略。
- 用户、grants、设备批准、有效会话和本地工具认证保持；迁移本身不扩大权限。
- 所有读写入口一致，重启与知识库搬迁不创建新的空认证库；并发或失败迁移可恢复。
- revision 写入、CSRF、公网 origin、本机服务识别和停止进程归属检查仍有效。
- 新旧状态无法分叉；回退处理最新数据而不是盲目覆盖。
